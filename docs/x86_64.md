# 原生 x86_64 构建与迁移状态

当前内核、libc 和仓库内构建的用户程序使用 x86_64 ELF64。`src/kernel/arch/x86_64/` 是当前架构实现，旧 i386 教程中的寄存器和地址不能直接用于当前用户程序。

## 构建

在仓库根目录准备 NASM、LLVM（clang、ld.lld、llvm-objcopy、llvm-ar）、Python 3、GNU Make、PowerShell、QEMU x86_64，以及 GCC 或 Zig 宿主 C 编译器。Limine、Lua 和部分媒体库已随仓库提供，NetSurf 依赖需单独拉取。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/fetch-netsurf.ps1
make doctor
make -j4
make run-local
```

Windows 下 Makefile 通过 `py -3` 解析 Python 实际路径，避免 WindowsApps 的占位程序。可传 `PYTHON="C:/.../python.exe"`、`QEMU="C:/Program Files/qemu/qemu-system-x86_64.exe"` 和 `HOST_CC="zig.exe cc"` 覆盖工具选择。

依赖拉取脚本按固定提交检出，复用同版本 checkout，并检查补丁是否已经应用。切换依赖版本前若有本地修改会报错，避免覆盖修改。默认 NetSurf 源为官方 Git 服务；`-RepositoryBase` 可替换为包含全部固定提交的镜像。

## 启动和 ABI

Limine BIOS 通过 Multiboot2 进入 32 位引导桩，随后设置分页并切换 long mode；这是 ELF64 内核中的引导入口，不代表用户态兼容 ELF32。默认 framebuffer 请求为 1600×900×32，实际分辨率取决于设备。

用户程序以 `-target x86_64-none-elf` 和 `-mcmodel=large` 编译，通过 `src/user/libc/user.ld` 链接。系统调用使用 `int 0x80`，RAX 为调用号和返回值，参数依次为 RDI、RSI、RDX、R10、R8；普通 C 函数使用 x86_64 调用约定。优先调用 libc 包装函数。

| 区域 | 范围或容量 |
| --- | --- |
| ELF 加载窗口 | `[0x100000000, 0x200000000)`，4–8 GiB |
| 显示映射 | 从 `0x200000000` 起，64 MiB |
| 共享内存 | 从 `0x210000000` 起，64 个 64 MiB 槽 |
| GPU 映射 | 从 `0x400000000` 起，64 个 64 MiB 槽 |
| GPU 预算 | 512 MiB；虚拟槽容量不等于物理内存承诺 |
| 主栈 | 顶部 `0x7FFFFFF00000`，8 MiB |
| 线程栈 | 每槽 1 MiB，256 个虚拟槽 |
| trampoline | `0x7FFFFFFFF000` |

加载器仅接受 little-endian x86_64 ELF64 可执行文件，检查文件边界、段大小、用户窗口和可执行入口。用户地址及 IPC 地址字段必须保持 `uintptr_t` 宽度；futex 等待队列已修复截断，诊断输出显示完整地址。

libc 的 malloc/calloc/realloc 保证 16 字节对齐，包含分裂和回收后的块，满足 x86_64 编译器对普通对象及 SSE 指令的对齐要求。PMM 管理地址上限为 `0xE0000000`（3.5 GiB），这与 QEMU 实际分配的 RAM 容量不同。

磁盘镜像的 FAT16 引导分区占 LBA 2048–67583；32 MiB minifs 占 LBA 67584–133119，拥有 2048 个 inode 和 63363 个数据块。默认镜像重建保留 `/fs`。

## 验证边界

```powershell
make host-test check-project uikit-test
make core-smoke
make gui-startup-smoke
make fs-check
```

`core-smoke` 覆盖原生 ELF64 正常与异常装载、指针校验、线程、futex、管道、文件系统、网络和 NetSurf 核心测试。它显式排除 basm/bcc 的旧产物执行测试。`gui-startup-smoke` 启动桌面及默认选中的应用，验证截图、退出和异常日志；它不验证所有窗口操作、媒体或游戏。

`make smoke`、`make gui-smoke` 和 `make verify` 保留完整历史测试范围。basm/bcc 后端仍使用 32 位编码、ELF32 和旧地址/调用约定，产物不能在当前内核执行；完整 GUI 测试还依赖游戏资源及历史窗口坐标。不能用上述有限验证宣称完整测试通过。`docs/assembly-programming.md` 和 `docs/tutorial.md` 中未迁移的 32 位示例仅供历史参考。
